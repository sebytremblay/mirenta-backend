# app/services/llm/ — model registry + fallback service

- **`registry.py`** — `LLMRegistry.LLMS` is a hardcoded list of pre-initialized `ChatOpenAI` instances (not lazy). `get(model_name, **kwargs)` returns the shared pre-built instance when called with no kwargs; passing any kwarg builds a **fresh** one-off `ChatOpenAI` instead, leaving the registry entry untouched. `get_model_at_index` wraps to index 0 out of range — used by the circular fallback below.
  - Registry entries note: `"gpt-5.4"` maps to model string `"gpt-5"` and `"gpt-5.4-nano"` maps to model string `"gpt-5.4-nano"` (not `"gpt-5-nano"`) — the registry `name` key and the actual `model=` string passed to `ChatOpenAI` diverge for two of the four entries. Check `registry.py` directly before assuming a registry name matches the real model string.

- **`service.py`** — `LLMService` (singleton `llm_service`, instantiated at import time) wraps the registry with two distinct call paths, both funneling through `_fallback_loop`:
  - **Default path** — no `model_name`/`response_format`/`model_kwargs` passed to `.call()`: uses `self._llm`, the tool-bound agent model (`bind_tools` mutates this). On failure, `_switch_to_next_model()` advances `self._llm` itself (circular through `LLMRegistry.LLMS`, re-binding tools each switch) — so a fallback here persists for subsequent default-path calls too.
  - **One-off path** — any override provided: resolves a fresh `Runnable` per attempt via `LLMRegistry.get(name, **model_kwargs)` (chained with `.with_structured_output()` if `response_format` is set), advancing a purely local index. Never touches `self._llm`, so concurrent default-path calls are unaffected.
  - Per-model retry (`_invoke_with_retry`, tenacity, up to `settings.MAX_LLM_CALL_RETRIES`) only catches `RateLimitError`/`APITimeoutError`/`APIError`; once those retries exhaust for one model, `_fallback_loop` moves to the next model in the registry rather than retrying the same one indefinitely. The whole call — all models, all retries — is bounded by `settings.LLM_TOTAL_TIMEOUT` seconds (`asyncio.wait_for` in `.call()`), raising `RuntimeError` on timeout regardless of how many models are left untried.
  - `bind_tools()` is called once per channel agent at `BaseChannelAgent.__init__` (see `app/core/langgraph/CLAUDE.md`) — both `SMSAgent` and `VoiceAgent` share this one `llm_service` singleton, so binding one channel's (currently empty) tool list affects the shared default-path model for both.
