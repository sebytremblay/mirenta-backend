# app/services/clients/ — external SDK wrappers

- **`supabase_client.py`** — `get_service_role_client()` (secret key, bypasses RLS entirely — agent-runtime writes only, never on behalf of a dashboard user) and `get_user_client(access_token)` (publishable key + forwarded JWT, so `auth.uid()` resolves for RLS). Both are cached (`get_service_role_client` via a module-level singleton + `asyncio.Lock`; `get_user_client` creates fresh per call since the token varies). `execute_query()` wraps `.execute()` with tenacity retry on `httpx.ConnectError`/`TimeoutException` only — `postgrest.exceptions.APIError` (RLS denial, not-found, validation) is never retried, since those are application-level responses. Every table access in the codebase goes through `execute_query`, not `.execute()` directly.

- **`twilio_client.py`** — the ISV subaccount pattern: each org gets its own Twilio subaccount + number + Messaging Service (`provision_org_twilio`), so subaccount API calls must authenticate with that subaccount's own SID+token (`get_twilio_client(account_sid=, auth_token=)`) — a parent-credentials-with-`account_sid`-override call 401s on several Twilio resources. The subaccount Auth Token is Fernet-encrypted at rest (`encrypt_twilio_auth_token`/`decrypt_twilio_auth_token`); `_fernet()` prefers `settings.TWILIO_TOKEN_ENCRYPTION_KEY` and falls back to deriving a stable key from `TWILIO_AUTH_TOKEN` for local dev only — set the explicit key in production.
  - `provision_org_twilio` deliberately does **not** retry the create/purchase/attach steps (only the read-only number search retries) — a timed-out-but-actually-succeeded create would leak orphaned Twilio resources on retry.
  - `generate_voice_dial_twiml` builds `<Dial><Sip>` TwiML pointing at `settings.LIVEKIT_SIP_URI`, encoding Mirenta correlation IDs (`X-Mirenta-Org-Id`, `-Contact-Id`, `-Signal-Id`, `-Call-Sid`) as query params on the `sip:` URI — Twilio forwards these as SIP INVITE headers, which the LiveKit inbound trunk config (`livekit_agent/sip/inbound-trunk.json`) maps to participant attributes for the agent to read (`call_context.py`).
  - `generate_voice_reject_twiml` is the fallback (speak message + hangup) used whenever the SIP bridge isn't configured or the call is blocked.

- **`temporal_client.py`** — `get_temporal_client()`, a cached singleton (`asyncio.Lock`-guarded) using `pydantic_data_converter` so workflows/activities can pass the app's existing Pydantic schemas (`Signal`, `Task`, ...) directly instead of hand-rolled dataclasses. Shared by both the FastAPI process (signal-with-start into `ContactLoopWorkflow`) and `worker/main.py`.

- **`livekit_client.py`** — currently just a docstring; reserved. Twilio→LiveKit SIP dial logic lives in `twilio_client.py` (above), and the LiveKit SIP trunk/dispatch rule itself is managed out-of-band via the `lk` CLI (`livekit_agent/sip/`), not through this module.
